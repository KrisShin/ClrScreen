# 隐私与安全

---

## 一句话结论

**本应用不联网，不采集、不上传任何数据。** 全部逻辑在本机完成，可自行审阅。

v1.1 为了后台保活新增了 5 个系统权限（前台服务、通知、电池优化、开机广播），**全部不涉及网络**。下面逐条说明。

---

## 一、权限清单

### 申请的系统权限（v1.1 起）

| 权限 | 用途 | 风险 |
|------|------|------|
| `FOREGROUND_SERVICE` | Android 9+ 启动前台服务 | 无。仅允许本应用创建前台服务 |
| `FOREGROUND_SERVICE_SPECIAL_USE` | Android 14+ 声明前台服务类型 | 无。需在清单中说明用途 |
| `POST_NOTIFICATIONS` | Android 13+ 显示常驻通知 | 无。只能发通知，且用户可随时关闭 |
| `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS` | 申请加入电池优化白名单 | 中低。会让系统不冻结本应用，需用户确认 |
| `RECEIVE_BOOT_COMPLETED` | 开机后恢复常驻通知 | 无。只接收开机广播 |

这些权限的**唯一目的**是让服务在后台活得更久。它们都无法读取用户数据、无法访问文件、无法联网。

### 特别注意：仍然没有 INTERNET 权限

这是最重要的一点。清单里**没有** `android.permission.INTERNET`：

- 应用**在系统层面无法发起任何网络请求**；
- 即使代码里写了联网逻辑也会直接抛 `SecurityException`；
- 不存在「偷偷上传数据」的可能——没有这个能力。

用 `aapt2` 验证：

```bash
aapt2 dump permissions app-debug.apk
```

输出只有包名和上面 5 个权限，**无 INTERNET**。

### 权限的取舍说明

早期版本（v1.0）确实是零权限。改成现在这样是因为：**没有前台服务的应用，在国产 ROM 上几乎必然被清理**，功能实际不可用。

如果你更看重零权限，可以只保留无障碍服务、关掉「常驻通知」开关——此时应用仍能工作，但被系统回收的概率显著上升。

## 二、无障碍服务是什么

这是本应用唯一使用的系统能力，也是最容易被误解的部分。

### 它不是普通权限

```xml
<service
    android:name=".SkipAdAccessibilityService"
    android:exported="false"
    android:permission="android.permission.BIND_ACCESSIBILITY_SERVICE">
```

`BIND_ACCESSIBILITY_SERVICE` 是**系统绑定机制**，不是用户授予的运行时权限。它保证只有系统能绑定这个服务，其他 App 无法调用它。

用户实际授予的，是在系统设置里手动打开「无障碍」开关——这是一个显式、可见、可随时关闭的授权。

### 它能做什么

开启后，服务可以：

| 能力 | 对应配置 | 本应用用途 |
|------|---------|-----------|
| 读取界面节点树 | `canRetrieveWindowContent="true"` | 查找「跳过」按钮 |
| 接收窗口事件 | `typeWindowStateChanged` / `typeWindowContentChanged` | 知道何时该扫描 |
| 执行点击 | `ACTION_CLICK` | 点击跳过按钮 |
| 派发手势 | `canPerformGestures="true"` | 兜底点击自绘控件 |

### 它实际做了什么

```kotlin
// 1. 只在窗口切换后的 6 秒内工作
if (now - lastWindowChangeAt > SPLASH_WATCH_WINDOW_MS) return

// 2. 只读节点树，找「跳过」类控件
val target = findSkipNode(root) ?: return

// 3. 点击它
if (clickNode(target)) { ... }
```

**没有其他操作。** 不读取输入框内容、不记录按键、不截屏、不存储任何界面信息。节点对象用完即弃，不缓存、不落盘。

## 三、数据处理

| 数据类型 | 是否接触 | 说明 |
|---------|---------|------|
| 网络数据 | ❌ | 无网络权限，无法联网 |
| 账号信息 | ❌ | 不读取任何账号相关界面 |
| 输入内容 | ❌ | 不读取 `EditText` 内容 |
| 通讯录 / 短信 / 相册 | ❌ | 无相关权限 |
| 位置信息 | ❌ | 无相关权限 |
| 设备标识 | ❌ | 不采集 IMEI、Android ID 等 |
| 界面节点文本 | ⚠️ 临时读取 | 仅在内存中打分，不存储、不上传 |
| 跳过次数 | ⚠️ 内存计数 | 整数，存在进程内存，进程结束即消失 |
| 保活开关偏好 | ⚠️ 本地存储 | 一个布尔值，存于 SharedPreferences |

### 关于「界面节点文本」

服务确实会读取当前窗口的节点树，这是实现功能的必要前提——不读就不知道屏幕上有没有「跳过」按钮。

但这些数据：

- **只在内存中存在**，方法返回后即可被 GC 回收；
- **不写入文件**，没有数据库、没有界面内容日志；
- **不发送到任何地方**，应用没有网络能力。

### 关于本地存储

v1.1 起用 `SharedPreferences` 保存**一个布尔值**：后台守护是否开启。文件内容形如：

```xml
<boolean name="keep_alive_enabled" value="true" />
```

不包含任何界面内容、时间戳或标识符。这是唯一的持久化数据。

### 关于日志

Debug 构建在点击成功时会打一行得分明细到 logcat，例如：

```
已点击 pkg=com.example score=105 [文案「跳过 5」+30, 控件ID含 skip +40, ...]
```

包含**包名和判定理由**，不包含界面上的其它文字内容。Release 构建中该日志由 `BuildConfig.DEBUG` 常量折叠移除。

如果连包名都不想暴露，可以把 `SkipAdAccessibilityService` 里的 `if (BuildConfig.DEBUG)` 整段删掉。

## 四、第三方组件

**零第三方依赖。**

`app/build.gradle.kts`：

```kotlin
// 无任何第三方依赖：应用不申请网络权限，完全离线运行
dependencies {
}
```

没有广告 SDK、没有统计 SDK、没有崩溃上报、没有网络库。所有代码都是项目自身约 400 行的 Kotlin + XML。

这直接消除了「第三方 SDK 偷偷收集数据」这类最常见风险。

### APK 里到底有什么

实际解包 `app-debug.apk` 的内容：

```
classes.dex / classes2.dex / classes3.dex      # 应用代码（含 Kotlin 标准库）
kotlin/*.kotlin_builtins                       # Kotlin 标准库内置数据
AndroidManifest.xml
res/drawable/ic_launcher.xml
res/layout/activity_main.xml
res/xml/accessibility_service_config.xml
resources.arsc
META-INF/.../app-metadata.properties
```

**没有** `.so` 原生库、**没有** assets 里的第三方 SDK、**没有**任何网络相关配置文件。

需要说明的是：`classes*.dex` 里包含 **Kotlin 标准库**（`kotlin.*` 运行时），这是 Kotlin 编译的必然产物，由 Kotlin Gradle 插件自动引入，不是额外添加的第三方依赖，也不含任何数据收集逻辑。

自行验证：

```bash
unzip -l app-debug.apk
```

## 五、风险与局限

### 无障碍服务的固有风险

任何无障碍服务都拥有很高的系统权限。这是 Android 的设计——为了辅助残障用户操作界面，必须能读取和操作屏幕。

风险在于：**恶意应用可能滥用这个权限**。

本项目的应对：

1. 代码完全公开可审阅；
2. **无网络权限**，即使想传数据也传不出去；
3. 无第三方依赖，不存在「夹带私货」的 SDK；
4. 唯一的持久化数据是一个布尔开关，不含界面内容。

### 新增权限带来的风险

v1.1 的保活权限中，最需要留意的是 `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS`：

- 加入白名单后，系统**不会**在 Doze 模式下冻结本应用；
- 这会让它比普通应用多消耗一点电（实测影响极小，因为服务空闲时不做事）；
- 它**不会**让应用获得读取数据的能力。

其余 4 个权限（前台服务、通知、开机广播）风险基本为零。

### 使用建议

- **只从可信来源安装**。APK 一旦被篡改，上述保证全部失效；
- 安装前可用 `aapt2 dump permissions xxx.apk` 确认权限列表符合预期（应无 `INTERNET`）；
- 不使用时在系统设置里关闭无障碍开关；
- 不需要后台保活时，关掉「常驻通知」开关即可；
- 如发现异常行为，立即关闭并卸载。

### 自动点击的副作用

服务会自动点击屏幕上判定为「跳过」的控件。评分制已把「跳过此步骤」「跳过教程」等引导文案列入排除词，实测不再误伤（见 [README · 实测结果](../README.md#实测结果)）。但任何自动点击方案都无法保证 100% 准确，使用时应有预期。

## 六、如何自行验证

### 验证权限列表

```bash
aapt2 dump permissions app-debug.apk
```

应输出包名 + 5 个保活权限，**无 `android.permission.INTERNET`**。

### 验证无网络行为

没有 `INTERNET` 权限的应用，在系统层面创建 socket 会直接抛 `SecurityException`：

```bash
adb shell dumpsys package com.clrscreen.skipad | grep -i "granted=true"
```

也可以挂 PC 端代理或抓包工具（Charles / mitmproxy），把手机流量导过去，然后正常使用本应用一段时间——不会有任何来自 `com.clrscreen.skipad` 的请求。

### 验证代码无网络调用

```bash
grep -rn "http\|Http\|Socket\|URL\|OkHttp\|Retrofit" app/src/main/java/
```

应无匹配（除注释）。本项目实测结果为空。

### 验证落盘数据

```bash
grep -rn "SharedPreferences\|FileOutputStream\|openFileOutput\|database" app/src/main/java/
```

只会命中 `Prefs.kt`（保存保活开关的布尔值），不应有其它匹配。

### 验证 APK 内容

```bash
unzip -l app-debug.apk
```

只有 `classes*.dex`、资源文件、清单、Kotlin 标准库内置数据，无第三方 `.so` 原生库。完整清单见上文 [APK 里到底有什么](#apk-里到底有什么)。

## 七、卸载后的残留

卸载应用后：

- 系统自动清理无障碍服务注册；
- 无任何数据文件残留（本来就没写）；
- 无后台进程残留。

个别 ROM 可能在无障碍设置里留下失效条目，重新进入设置页会自行消失。
