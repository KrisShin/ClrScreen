## 一、环境要求

| 项目 | 要求 | 本项目使用 |
|------|------|-----------|
| JDK | **17 ~ 21** | JDK 21（实测通过） |
| Android SDK | Platform 34 | compileSdk / targetSdk = 34 |
| Build Tools | 34.0.0 | 34.0.0 |
| Gradle | 由 wrapper 提供 | 8.7 |
| Android Gradle Plugin | — | 8.5.2 |
| Kotlin | — | 1.9.24 |

### 关于 JDK 版本（重要）

**不要用 JDK 22 及以上**。Gradle 8.7 不支持 Java 26，会直接报错：

```
* What went wrong:
26
```

这是 Gradle 8.7 对高版本 JVM 的兼容性限制，不是项目配置问题。用 JDK 17 或 21 即可。

检查当前 JDK：

```bash
java -version
```

如需切换（Windows）：

```powershell
$env:JAVA_HOME = "C:\Program Files\Java\jdk-21"
```

或设置到系统环境变量 `JAVA_HOME`。

### Android SDK 配置

`local.properties` 记录本机 SDK 路径，**已被 `.gitignore` 排除**，不要提交：

```properties
sdk.dir=C\:\\Users\\<你的用户名>\\AppData\\Local\\Android\\Sdk
```

换机器后重新生成或手写这一行即可。

## 二、构建命令

Windows 下用 `.\gradlew.bat`，macOS / Linux 用 `./gradlew`。

| 命令 | 作用 | 产物 |
|------|------|------|
| `assembleDebug` | 构建调试包 | `app/build/outputs/apk/debug/app-debug.apk` |
| `installDebug` | 构建并安装到已连接设备 | — |
| `assembleRelease` | 构建发布包（**未签名**） | `app/build/outputs/apk/release/app-release-unsigned.apk` |
| `lintDebug` | 静态检查 | `app/build/reports/lint-results-debug.html` |
| `clean` | 清理产物 | — |

### 常用组合

```bash
# 本地跑起来
./gradlew installDebug

# 打包给别人
./gradlew assembleDebug
# 产物约 800 KB

# 检查代码质量
./gradlew lintDebug
```

### 离线构建

首次构建需要联网下载 AGP、Kotlin 插件等依赖。之后可以加 `--offline` 走本地缓存：

```bash
./gradlew assembleDebug --offline
```

### 仓库镜像

`settings.gradle.kts` 已把阿里云镜像放在官方源前面，国内网络下更快：

```kotlin
maven("https://maven.aliyun.com/repository/google")
maven("https://maven.aliyun.com/repository/public")
google()
mavenCentral()
```

Gradle 分发包用的是腾讯云镜像（`gradle/wrapper/gradle-wrapper.properties`）：

## 三、发布签名

签名已配置为 **Gradle 自动完成**，不需要手工 `zipalign` + `apksigner`。

### 快速开始

1. 把 keystore 放在工作区外（避免误提交），例如 `C:\Users\HP\WorkSpace\clrscreen-signing\clrscreen-release.jks`
2. 在项目根目录创建 `keystore.properties`（已 gitignore）：

```properties
storeFile=../clrscreen-signing/clrscreen-release.jks
storePassword=你的密码
keyAlias=clrscreen
keyPassword=你的密码
```

3. 构建：

```bash
./gradlew assembleRelease
```

产物 `app/build/outputs/apk/release/app-release.apk` **已签名可直接安装**。

### 签名配置的读取顺序

`app/build.gradle.kts` 优先读环境变量（CI 用），其次读 `keystore.properties`（本地用）：

```
SIGNING_STORE_FILE / SIGNING_STORE_PASSWORD / SIGNING_KEY_ALIAS / SIGNING_KEY_PASSWORD
        ↓ 没有则
keystore.properties 的 storeFile / storePassword / keyAlias / keyPassword
        ↓ 都没有
产出未签名包（assembleDebug 不受影响）
```

> **路径坑**：`storeFile` 的相对路径按**项目根目录**解析，不是 `app/` 目录。所以工作区外的密钥写 `../clrscreen-signing/xxx.jks`。

### 验证签名

```powershell
$BT = "$env:LOCALAPPDATA\Android\Sdk\build-tools\34.0.0"
& "$BT\apksigner.bat" verify --verbose --print-certs app\build\outputs\apk\release\app-release.apk
```

预期输出：

```
Verifies
Verified using v2 scheme (APK Signature Scheme v2): true
Verified using v3 scheme (APK Signature Scheme v3): true
Signer #1 certificate DN: CN=ClrScreen, OU=Android, O=ClrScreen, L=Unknown, ST=Unknown, C=CN
```

> v1 显示 `false` 是正常的：`minSdk = 24` 时 AGP 默认不启用 v1（JAR signing）。Android 7.0+ 用 v2/v3 即可。

### 手动签名（备用）

如果需要在没有 `keystore.properties` 的机器上临时签名：

```powershell
$BT = "$env:LOCALAPPDATA\Android\Sdk\build-tools\34.0.0"

& "$BT\zipalign.exe" -p -f 4 `
  app\build\outputs\apk\release\app-release-unsigned.apk `
  app\build\outputs\apk\release\app-release-aligned.apk

& "$BT\apksigner.bat" sign `
  --ks clrscreen-release.jks --ks-key-alias clrscreen `
  --out app\build\outputs\apk\release\app-release-signed.apk `
  app\build\outputs\apk\release\app-release-aligned.apk
```

### ⚠️ 密钥备份

**务必备份 keystore 与密码。** 丢失后无法对已发布应用做覆盖升级，用户必须卸载重装。

完整说明（含 GitHub Actions 自动发布）见 [发布与签名](发布与签名.md)。

### 关于 demo 模块

`demo` 是一个独立的 APK（包名 `com.clrscreen.skipad.demo`），用于验证判定规则。它：

- **不随正式包分发** —— 独立安装，卸载主应用不受影响；
- **零依赖** —— 和主应用一样不引入任何第三方库；
- **可扩展** —— 加新场景只需改 `Scenario.kt` 枚举 + `AdScenarioActivity.buildScenario()` 一个分支。

```bash
./gradlew :demo:installDebug      # 只构建靶场
./gradlew :app:installDebug       # 只构建主应用
./gradlew installDebug            # 两个都装
```

### 权限说明

v1.1 新增 5 个权限，全部服务于保活：

```xml
<uses-permission android:name="android.permission.FOREGROUND_SERVICE" />
<uses-permission android:name="android.permission.FOREGROUND_SERVICE_SPECIAL_USE" />
<uses-permission android:name="android.permission.POST_NOTIFICATIONS" />
<uses-permission android:name="android.permission.REQUEST_IGNORE_BATTERY_OPTIMIZATIONS" />
<uses-permission android:name="android.permission.RECEIVE_BOOT_COMPLETED" />
```

**没有 `INTERNET`。** 这是刻意保留的红线，改动时不要破坏。

`FOREGROUND_SERVICE_SPECIAL_USE` 需要配合 `<property>` 声明用途（Android 14+ 要求）：

```xml
<service
    android:name=".KeepAliveService"
    android:exported="false"
    android:foregroundServiceType="specialUse">
    <property
        android:name="android.app.PROPERTY_SPECIAL_USE_FGS_SUBTYPE"
        android:value="保持开屏提醒服务在后台可用" />
</service>
```

### SkipRuleEngine.kt —— 判定核心

这是 v1.1 最重要的新增。设计上刻意不依赖 Android：

```kotlin
data class NodeSnapshot(...)          // 从 AccessibilityNodeInfo 抽出的纯数据
sealed interface Verdict {
    data class Hit(val score: Int, val reasons: List<String>) : Verdict
    data class Miss(val score: Int, val reasons: List<String>) : Verdict
}
object SkipRuleEngine {
    const val CLICK_THRESHOLD = 50
    fun evaluate(node: NodeSnapshot): Verdict
}
```

好处：判定逻辑可以脱离设备推演。想知道某个控件会不会被点，构造一个 `NodeSnapshot` 调 `evaluate()` 即可。

打分流程：

```
前置否决（enabled / visible / 尺寸）
    ↓
排除词检查（命中直接 Miss(-1000)）
    ↓
累加：文案 + 描述 + ID + 位置 + 尺寸 + 可点击性 + 控件类型
    ↓
score >= 50 ? Hit : Miss
```

完整分值表见 [工作原理 · 识别：评分制](工作原理.md#识别评分制)。

## 六、可调参数

按需求调整，改完重新构建即可。

### 想覆盖更慢的广告

```kotlin
// SkipAdAccessibilityService.kt
private const val SPLASH_WATCH_WINDOW_MS = 12000L   // 8s → 12s
private val SCAN_DELAYS_MS = longArrayOf(
    0, 250, 600, 1000, 1500, 2100, 2800, 3600, 4500, 5600, 6500, 8000, 10000
)
```

代价：扫描次数变多，耗电略增；误伤概率也会上升。

### 想减少误触

两个旋钮，可以叠加：

**1. 加排除词**（推荐，最精准）

```kotlin
// SkipRuleEngine.kt
private val EXCLUDE_PHRASES = listOf(
    "跳过此步骤", "跳过本步骤", "跳过教程", "跳过引导", "跳过设置",
    "跳过验证", "跳过登录", "跳过片头", "跳过片尾", "跳过介绍", "跳过说明",
    // 新增你想排除的：
    "跳过这节", "跳过推荐",
)
```

**2. 调高阈值**

```kotlin
const val CLICK_THRESHOLD = 60   // 默认 50
```

阈值越高越保守。50 分时，单个「文案含关键词 +10 可点击」的弱候选刚好不够（30+10=40），需要再叠加位置或尺寸信号才命中。

**3. 缩短观察窗口**

```kotlin
private const val SPLASH_WATCH_WINDOW_MS = 4000L   // 8s → 4s
```

### 想支持更多语言

在 `SkipRuleEngine` 的 `SKIP_KEYWORDS` 里加：

```kotlin
private val SKIP_KEYWORDS = listOf(
    "跳过", "跳過", "skip",
    "건너뛰기",    // 韩语
    "スキップ",     // 日语
    "passer",      // 法语
)
```

如果该语言的跳过按钮文案是固定短词，也可以加进 `EXACT_SKIP_TEXTS` 拿 +45 高分。

### 想让计数持久化

`skipCount` 目前是内存字段。改成 `SharedPreferences`：

```kotlin
// 在 SkipAdAccessibilityService 中
private fun bumpCount() {
    skipCount += 1
    getSharedPreferences("stats", MODE_PRIVATE)
        .edit().putInt("count", skipCount).apply()
}

// 在 onServiceConnected 中恢复
skipCount = getSharedPreferences("stats", MODE_PRIVATE).getInt("count", 0)
```

对应把 `strings.xml` 里的「本次运行以来」改成「累计」。

### 想加判定日志

Debug 构建已经内置了判定得分日志，无需自己加：

```kotlin
if (BuildConfig.DEBUG) {
    android.util.Log.d(TAG, "已点击 pkg=$pkg score=${candidate.verdict.score} ${candidate.verdict.reasons}")
}
```

用 `adb logcat -s ClrScreen:D` 观察：

```
已点击 pkg=com.example score=105 [无障碍描述「跳过 5」+30, 控件ID含 skip +40,
  位于右下角 +15, 控件面积小(1%) +10, 自身可点击 +10]
```

排查「为什么没点」时，把 `SkipRuleEngine.CLICK_THRESHOLD` 临时设为 `Int.MIN_VALUE`，所有候选都会打出来——但注意此时任何节点都会被点，只在靶场上用。

## 七、测试

判定逻辑 `SkipRuleEngine` 是纯函数，理论上可以写 JVM 单元测试。但项目当前**没有单元测试**，原因：

1. 项目刻意保持零第三方依赖，加 JUnit 会引入 `junit:junit`；
2. 真正的问题（WebView 点击失效、事件时序）都在框架层，单元测试覆盖不到；
3. 用自带靶场做端到端验证，性价比更高。

### 自带靶场（推荐）

项目包含 `demo` 模块，实现了 22 种广告形态：

```bash
./gradlew :demo:installDebug
```

装好后打开「ClrScreen 靶场」，逐个点击场景。每个场景会自动记录结果到 logcat：

```bash
adb logcat -s ClrScreenDemo:I
```

输出形如：

```
SHOWN id=text_plain
SKIPPED id=text_plain reason=CLICKED
FALSE_POSITIVE id=guide_skip_step
```

### 自动化回归

```bash
pwsh -File tools/run-scenarios.ps1 -Label final
```

脚本会逐个启动场景、采集日志、对比期望，输出通过率并保存 CSV：

```
text_plain             expect=SKIP    actual=CLICKED         PASS
guide_skip_step        expect=IGNORE  actual=NO_CLICK        PASS
...
===== final : PASS=19 FAIL=0 =====
```

改动判定规则后跑一遍，能立刻看出有没有回归。

### 靶场场景一览

| 分类 | 场景 |
|------|------|
| 应当跳过 | `text_plain` `text_corner` `desc_only` `view_id_skip` `child_text` `touch_only` `english` `delayed_3s` `timer_countdown` `transparent_overlay` `deep_nested` `close_ad_text` `countdown_prefix` `skip_in_webview` `fullscreen_clickable` |
| 应当忽略 | `guide_skip_step` `guide_skip_tutorial` `long_sentence` `video_seek` |
| 观察项 | `canvas_drawn` `image_button` `late_8s` |

定义在 `demo/src/main/java/com/clrscreen/skipad/demo/Scenario.kt`，加新场景只需在枚举里加一项、在 `AdScenarioActivity.buildScenario()` 里加一个分支。

### 用 adb 免手动开启服务

调试时反复进设置很烦，可以直接写系统设置：

```bash
adb shell settings put secure enabled_accessibility_services \
  com.clrscreen.skipad/com.clrscreen.skipad.SkipAdAccessibilityService
adb shell settings put secure accessibility_enabled 1
```

验证绑定状态：

```bash
adb shell dumpsys accessibility | grep -A2 "Bound services"
```

> **坑**：`adb shell am force-stop com.clrscreen.skipad` 会**清空**上述两个设置项（系统认为用户主动停用了应用）。测完要重新执行上面的命令。

### 查看界面节点树

想确认某个 App 的跳过按钮长什么样：

```bash
adb shell uiautomator dump /sdcard/ui.xml
adb shell cat /sdcard/ui.xml
```

在输出里搜「跳过」，看它的 `text`、`resource-id`、`clickable`、`bounds`，就能判断走哪一级点击策略。

## 八、修改时的注意事项

1. **别加 `INTERNET` 权限。** 项目的核心卖点是纯离线。保活用的 5 个权限已经是必要上限，再加网络权限会破坏这个承诺。
2. **别加第三方依赖。** 零依赖是特性，APK 才能压在 620 KB。
3. **改文案要同步改 `strings.xml`**，布局里用的是 `@string/` 引用。
4. **改 `SYSTEM_PACKAGES` 要谨慎**，漏掉系统包可能导致开机向导被误点。
5. **不要在主线程做重活**，事件回调本身在主线程，节点遍历必须保持轻量。
6. **`AccessibilityNodeInfo` 用完不 recycle** —— 从 API 33 起 `recycle()` 已废弃且是空操作，代码里直接交给 GC，这是正确做法。
7. **改判定规则后跑一遍靶场回归**，确认没有引入误伤。
8. **改 `SKIP_KEYWORDS` 要小心子串误伤** —— 例如加 `"skip"` 时，`"skipper"`、`"skipping"` 也会命中，靠排除词和阈值兜底。
