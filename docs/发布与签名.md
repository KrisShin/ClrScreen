# 发布与签名

本文说明如何签名打包、如何发版，以及 GitHub Actions 自动发布流水线的工作方式。

---

## 一、签名密钥

### 密钥在哪

| 项目 | 位置 |
|------|------|
| keystore 文件 | `C:\Users\HP\WorkSpace\clrscreen-signing\clrscreen-release.jks`（**工作区之外**） |
| 本地密码配置 | 项目根目录 `keystore.properties`（已 gitignore） |
| CI 用密钥 | GitHub Secrets（见下） |

> **keystore 刻意放在工作区之外**，从物理上杜绝 `git add -A` 误提交的可能。

### 关键信息

```
别名（alias）: clrscreen
算法: RSA 2048
有效期: 10000 天
证书 DN: CN=ClrScreen, OU=Android, O=ClrScreen, L=Unknown, ST=Unknown, C=CN
SHA-256: 70e0687bacefe4f62fe05a62ec9df79d1fdd75d3a34a9f97d1246febe511fe00
```

### ⚠️ 必须做的事

**立刻备份 `clrscreen-release.jks` 和它的密码到安全的地方**（密码管理器 / 加密网盘）。

丢失的后果：**无法对已发布的应用做覆盖升级**。用户必须卸载重装，且 Android 会把它当成另一个应用。

密码目前只存在于：
- `keystore.properties`（本机）
- GitHub Secrets（KEYSTORE_PASSWORD / KEY_PASSWORD）

## 二、本地签名打包

### 首次配置

`keystore.properties`（已在 `.gitignore` 中，不会提交）：

```properties
storeFile=../clrscreen-signing/clrscreen-release.jks
storePassword=你的密码
keyAlias=clrscreen
keyPassword=你的密码
```

> `storeFile` 的相对路径按**项目根目录**解析，不是 `app/` 目录。

### 打包

```bash
./gradlew assembleRelease
```

产物：`app/build/outputs/apk/release/app-release.apk`

构建日志会明确提示签名状态：

```
[ClrScreen] Release 签名已配置，将产出可直接安装的 APK
```

没配置签名时则提示：

```
[ClrScreen] 未找到签名配置，release 包将是未签名状态
```

### 验证签名

```bash
$BT = "$env:LOCALAPPDATA\Android\Sdk\build-tools\34.0.0"
& "$BT\apksigner.bat" verify --verbose --print-certs app\build\outputs\apk\release\app-release.apk
```

预期输出：

```
Verifies
Verified using v2 scheme (APK Signature Scheme v2): true
Verified using v3 scheme (APK Signature Scheme v3): true
Signer #1 certificate DN: CN=ClrScreen, OU=Android, O=ClrScreen, L=Unknown, ST=Unknown, C=CN
```

> v1 签名显示 `false` 是正常的：`minSdk = 24` 时 AGP 默认不启用 v1（JAR signing），Android 7.0+ 用 v2/v3 即可。若需支持 Android 6 及以下才需要 v1。

### 签名配置的读取顺序

`app/build.gradle.kts` 按优先级读取：

1. **环境变量**（CI 用）
   - `SIGNING_STORE_FILE` / `SIGNING_STORE_PASSWORD` / `SIGNING_KEY_ALIAS` / `SIGNING_KEY_PASSWORD`
2. **`keystore.properties`**（本地用）
   - `storeFile` / `storePassword` / `keyAlias` / `keyPassword`

两者都没有 → release 产出未签名包，`assembleDebug` 不受影响。

## 三、GitHub Actions 自动发布

### 工作流文件

`.github/workflows/release.yml`

### 触发方式

| 方式 | 行为 |
|------|------|
| 推送 `v*` 标签（如 `v1.2.0`） | 构建 + 签名 + **创建 GitHub Release** |
| 手动触发（workflow_dispatch） | 只构建，产物传为 Actions artifact，不发版 |

### 发版流程

```bash
# 1. 改版本号（app/build.gradle.kts）
#    versionCode = 3
#    versionName = "1.2"

# 2. 提交
git add -A
git commit -m "chore(release): v1.2"

# 3. 打标签并推送（tag 必须带 v 前缀）
git tag v1.2
git push origin main --tags
```

推送 tag 后，Actions 会自动：

1. 检出代码、装 JDK 17、恢复 Gradle 缓存
2. 从 `KEYSTORE_BASE64` 还原 keystore 到临时目录
3. 用环境变量注入签名信息，构建 release APK
4. 用 `apksigner` 校验签名（失败则整个流程失败）
5. 重命名为 `ClrScreen-<version>.apk`
6. 创建 Release 并附上 APK

### 需要的 Secrets

| Secret | 内容 |
|--------|------|
| `KEYSTORE_BASE64` | keystore 文件的 Base64 |
| `KEYSTORE_PASSWORD` | keystore 密码 |
| `KEY_ALIAS` | `clrscreen` |
| `KEY_PASSWORD` | key 密码 |

设置命令：

```bash
base64 -w0 clrscreen-release.jks | gh secret set KEYSTORE_BASE64 --repo KrisShin/ClrScreen
gh secret set KEYSTORE_PASSWORD --repo KrisShin/ClrScreen
gh secret set KEY_ALIAS --repo KrisShin/ClrScreen
gh secret set KEY_PASSWORD --repo KrisShin/ClrScreen
```

Windows PowerShell 下：

```powershell
$b64 = [Convert]::ToBase64String([System.IO.File]::ReadAllBytes("path\to\keystore.jks"))
$b64 | gh secret set KEYSTORE_BASE64 --repo KrisShin/ClrScreen
```

### 手动触发一次验证

```bash
gh workflow run release.yml --repo KrisShin/ClrScreen
gh run list --repo KrisShin/ClrScreen --limit 3
gh run watch
```

手动触发默认 `dry_run = true`，只构建不发版，适合验证流水线。

## 四、仓库是 Public，这意味着什么

`KrisShin/ClrScreen` 是**公开仓库**，因此：

| 项目 | 状态 |
|------|------|
| 源代码 | 公开可见 |
| keystore 文件 | ❌ 不在仓库里（gitignore + 放在工作区外） |
| keystore 密码 | ❌ 不在仓库里（只在本地 + Secrets） |
| GitHub Secrets | 加密存储，即使仓库公开也不可读 |

**Secrets 在公开仓库中的安全性**：GitHub Actions 的 Secrets 不会暴露给 fork 的 PR（除非配置了 `pull_request_target` 且误用）。本工作流只由 tag 推送和手动触发，不接受来自 fork 的输入，因此是安全的。

**注意**：不要在 workflow 里 `echo` 任何 secret，也不要把它写进构建产物。当前工作流只把密码通过环境变量传给 Gradle，不打印。

## 五、常见问题

### `Keystore file 'xxx' not found`

`storeFile` 路径解析错误。注意本文件在 `app/` 目录，但相对路径按**项目根目录**解析。用 `../clrscreen-signing/xxx.jks` 指到工作区外。

### `INSTALL_FAILED_UPDATE_INCOMPATIBLE: signatures do not match`

手机上装的是用另一个密钥签名的版本（通常是 debug 包）。必须先卸载：

```bash
adb uninstall com.clrscreen.skipad
adb install app-release.apk
```

**这个错误在用户侧也意味着：换密钥后无法覆盖升级。** 所以密钥必须妥善备份。

### Actions 报 `缺少 secret KEYSTORE_BASE64`

Secret 没配置或名字拼错。检查：

```bash
gh secret list --repo KrisShin/ClrScreen
```

### Release 没自动创建

- 确认 tag 以 `v` 开头（`v1.2` 可以，`1.2` 不行）
- 确认工作流文件已提交到默认分支 `main`
- 检查 Actions 页面是否有失败记录

### 想改用 tag 触发的其他格式

修改 `.github/workflows/release.yml` 的 `on.push.tags`：

```yaml
on:
  push:
    tags:
      - 'v*'        # v1.2, v1.2.0
      - 'release-*' # release-1.2
```

## 六、版本号约定

当前 `versionCode = 2` / `versionName = "1.1"`。

发新版时**两处都要改**：

```kotlin
versionCode = 3        // 必须递增，Android 用它判断新旧
versionName = "1.2"    // 展示给用户
```

`versionCode` 只增不减，否则无法覆盖安装。

建议让 git tag 与 `versionName` 保持一致：

```
tag:  v1.2
versionName = "1.2"
```
