# 常见问题

---

## 安装与开启

### 装完打开是「✖ 无障碍服务未开启」，正常吗？

正常。装完必须手动去系统设置里开启一次，这是 Android 对无障碍服务的强制要求，应用无法自己打开。

点界面上的「去开启无障碍服务」，在列表里找到「跳过开屏广告」并打开开关。

详见 [使用指南 · 开启服务](使用指南.md#二开启服务必做)。

---

### 系统设置里找不到「跳过开屏广告」

按系统找对应路径：

| 系统 | 路径 |
|------|------|
| 原生 / Pixel | 设置 → 无障碍 → 已下载的应用 |
| 小米 / Redmi | 设置 → 更多设置 → 无障碍 → 已下载的应用 |
| 华为 / 荣耀 | 设置 → 辅助功能 → 无障碍 → 已安装的服务 |
| OPPO / 一加 / realme | 设置 → 系统设置 → 无障碍 → 已安装的服务 |
| vivo / iQOO | 设置 → 快捷与辅助 → 无障碍 → 已下载的服务 |
| 三星 | 设置 → 辅助功能 → 已安装的应用 |

或在设置顶部搜索框直接搜「无障碍」。部分系统需要先点进「已下载的应用」二级菜单。

---

### 开启时系统弹窗说「可以查看和控制屏幕」，安全吗？

这是 Android 对无障碍服务的**标准提示**，任何无障碍服务都会触发，无法绕过。

本应用虽然拥有这个能力，但代码里只用它做三件事：读节点树找「跳过」、接收窗口事件、点击该按钮。**没有网络权限**，读到的内容传不出去。

详见 [隐私与安全](隐私与安全.md)。

---

### 开了之后要我登录 / 要权限，正常吗？

**不正常。** 本应用没有任何登录流程，也不申请敏感权限。如果出现这类界面，说明 APK 被篡改或来源不可信，请立即卸载。

> 说明：v1.1 会申请「忽略电池优化」和「通知」权限，这是保活所需，属于预期内的系统弹窗。除此之外不应有任何权限请求。

---

## 使用效果

### 为什么有些 App 的开屏提示能跳过，有些不能？

取决于该广告的实现方式：

| 情况 | 能否跳过 | 原因 |
|------|---------|------|
| 标准按钮，文字「跳过 5」 | ✅ | 标准场景 |
| 只有无障碍描述 | ✅ | 描述信号有效 |
| 控件 ID 带 skip | ✅ | ID 信号有效 |
| 文字在子节点、父容器处理点击 | ✅ | 祖先回溯 |
| 不可点击，仅触摸监听 | ✅ | 手势兜底 |
| 英文「Skip Ad」 | ✅ | 英文匹配 |
| 按钮延迟几秒出现（<6.5s） | ✅ | 11 次重扫覆盖 |
| 「关闭」类文案 | ✅ | 精确匹配表覆盖 |
| 「5s \| 跳过」组合文案 | ✅ | contains 匹配 |
| WebView 内的 H5 按钮 | ✅ | 优先手势点击 |
| 自绘 Canvas 画的按钮 | ❌ | 无障碍树里没有文字和 ID |
| 纯图片按钮 | ❌ | 同上 |
| 按钮 8 秒后才出现 | ❌ | 超出观察窗口（6.5 秒定时 + 内容事件到 8 秒） |
| 没有跳过按钮，只能等倒计时 | ❌ | 无目标可点 |
| 文案超过 12 字 | ❌ | 不参与文案打分 |

以上全部经过实测验证，详见 [README · 实测结果](../README.md#实测结果)。

---

### 自绘按钮为什么识别不了？

部分广告把「跳过」两个字直接画在 Canvas 上，或者用图片代替文字。这种实现下，无障碍树里对应的节点**没有 `text`、没有 `contentDescription`、也没有带 skip 的 ID**——只有一块矩形区域。

任何基于无障碍的方案都读不到它。这是技术边界，不是本应用的缺陷。

除非用图像识别（需要截屏权限，且耗电、慢、准确率低），否则无解。

---

### 为什么有的广告要点两下才跳过？

可能是这两种情况：

1. **第一次点击落在了广告本体的可点区域**（跳转落地页被拦截），第二次才点到跳过按钮；
2. **WebView 广告的首次点击被网页吞掉**，服务在 1.2 秒冷却后重试。

第二种情况在 v1.1 已优化为优先手势点击，命中率明显提升。

---

### 为什么要限制 12 个字？我的广告按钮文案很长

这是**防止误点**的保护。

广告页上常有说明性长句包含「跳过」，例如「点击跳过可直接进入应用首页」。如果不限长度，这类句子会被当成按钮点击。

真实的跳过按钮文案极少超过 12 字，最长常见形式是「跳过 5s」（4 字）。

注意：超过 12 字只是**不参与文案打分**，如果该节点有 `skip` 的 ID 或描述，仍可能靠其它信号达标。

如需放宽，改 `SkipRuleEngine.MAX_TEXT_LENGTH`，见 [开发指南 · 可调参数](开发指南.md#六可调参数)。

---

### 为什么 8 秒后才出现的按钮不点？

为了防误触。

开屏广告通常在启动后 3~5 秒内就渲染出跳过按钮。把观察窗口限制在 8 秒，可以让正常页面里长期存在的「跳过此步骤」落在窗口之外。

具体来说：定时扫描覆盖 0~6.5 秒，6.5~8 秒之间靠界面内容变化事件触发扫描。如果那段时间界面没有任何变化，就扫不到——所以延迟 8 秒的按钮是「临界状态」，时中时不中。

代价就是放弃极慢的广告。如需调整，`SPLASH_WATCH_WINDOW_MS` 和 `SCAN_DELAYS_MS` 要一起改。

---

### 误点了不该点的东西

**v1.1 起这个问题已基本解决。** 「跳过此步骤」「跳过教程」「跳过片头」「跳过引导」等 11 个词组已列入排除词，命中即否决，不再参与打分。

实测中这些场景全部不再被点（见 [README · 实测结果](../README.md#实测结果)）。

如果你仍遇到误点，说明遇到了排除词没覆盖的新文案。两个办法：

1. **临时**：把该文案加进 `EXCLUDE_PHRASES` 列表；
2. **调阈值**：把 `CLICK_THRESHOLD` 从 50 调高（如 60），减少弱信号叠加造成的命中。

代码位置见 [开发指南 · 可调参数](开发指南.md#六可调参数)。

---

### 跳过次数不准确 / 归零了

计数存在**进程内存**里，进程被系统回收后归零。

- 主界面只在 `onResume` 时刷新，看到的是进入界面那一刻的值；
- 文案是「本次运行以来」，就是字面意思；
- 不是持久统计，重启手机或应用被杀都会清零。

想改成持久化，见 [开发指南 · 想让计数持久化](开发指南.md#想让计数持久化)。

## 服务稳定性与保活

### 服务老是自动关闭

v1.1 已经内置了保活措施（前台服务 + 电池白名单 + 开机自恢复）。如果仍然被关闭，先确认主界面两个状态都是 ✔：

1. **无障碍服务已开启**
2. **已加入电池优化白名单**

然后按厂商补设：

| 系统 | 设置位置 |
|------|---------|
| 小米 / Redmi | 设置 → 应用设置 → 应用管理 → ClrScreen → 省电策略 → 无限制；最近任务里锁定 |
| 华为 / 荣耀 | 设置 → 电池 → 应用启动管理 → ClrScreen → 关闭「自动管理」，全部允许 |
| OPPO / 一加 / realme | 设置 → 电池 → 应用耗电管理 → ClrScreen → 允许后台运行 |
| vivo / iQOO | 设置 → 电池 → 后台高耗电 → 允许 ClrScreen |
| 三星 | 设置 → 电池 → 后台使用限制 → 从「休眠应用」中移除 |

另外检查是否开了「开发者选项 → 不保留活动」，开了会导致服务频繁重启。

完整说明见 [保活指南](保活指南.md)。

---

### 为什么加了权限？以前不是零权限吗？

v1.0 确实是零权限，但**没有前台服务的应用在国产 ROM 上几乎必然被清理**，功能实际不可用。

v1.1 新增了 5 个权限，全部服务于保活，**都不涉及网络**：

| 权限 | 用途 |
|------|------|
| `FOREGROUND_SERVICE` | 启动前台服务 |
| `FOREGROUND_SERVICE_SPECIAL_USE` | Android 14+ 前台服务类型声明 |
| `POST_NOTIFICATIONS` | 显示常驻通知 |
| `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS` | 加入电池优化白名单 |
| `RECEIVE_BOOT_COMPLETED` | 开机后恢复常驻通知 |

**`INTERNET` 权限依然没有**，应用仍然无法联网。

如果你更看重零权限，可以关掉主界面的「常驻通知」开关，此时只剩无障碍服务在工作，代价是稳定性下降。

---

### 状态栏那条通知能去掉吗？

可以。主界面「常驻通知（前台服务）」开关关掉即可。

但要知道代价：关掉后进程变成普通后台进程，更容易被系统回收，可能过一段时间发现服务不工作了。

这条通知是 Android 的硬性要求——前台服务必须挂通知，无法静默。

---

### 重启手机后要重新开启吗？

**不需要。**

实测确认：无障碍服务由系统托管，重启后自动重新绑定，`enabled_accessibility_services` 设置保持不变。

前台服务也会通过 `BOOT_COMPLETED` 广播自动恢复，进程会自行拉起。

前提是：你没有在系统里禁用 ClrScreen 的自启动权限。

---

### 更新版本后服务没了

覆盖安装后通常需要重新授权一次，重新走一遍开启流程即可。`MY_PACKAGE_REPLACED` 广播会自动恢复前台服务。

---

### 用 adb 开启的服务，一 force-stop 就没了

这是 Android 的行为：`adb shell am force-stop` 会**清空** `enabled_accessibility_services` 和 `accessibility_enabled` 两个设置项（系统视为用户主动停用）。

调试时重新执行：

```bash
adb shell settings put secure enabled_accessibility_services \
  com.clrscreen.skipad/com.clrscreen.skipad.SkipAdAccessibilityService
adb shell settings put secure accessibility_enabled 1
```

## 开发相关

### 构建报错 `* What went wrong: 26`

JDK 版本太高。Gradle 8.7 不支持 Java 26。

改用 **JDK 17 或 21**：

```powershell
$env:JAVA_HOME = "C:\Program Files\Java\jdk-21"
```

详见 [开发指南 · 关于 JDK 版本](开发指南.md#关于-jdk-版本重要)。

---

### `gradlew` 报 `FileNotFoundException ... .lck 拒绝访问`

Gradle wrapper 无法在 `~/.gradle` 写锁文件，通常是权限或沙箱限制。

解决：确保当前用户对 `%USERPROFILE%\.gradle` 有写权限，或直接在 IDE（Android Studio）里构建。

---

### 构建成功但 `app-release-unsigned.apk` 装不上

`assembleRelease` 产出的是**未签名**包，必须签名后才能安装。

签名步骤见 [开发指南 · 发布签名](开发指南.md#三发布签名)。

---

### 有单元测试吗？

没有 JVM 单元测试——核心逻辑强依赖 `AccessibilityNodeInfo` 和 `AccessibilityService`，两者都需要真实系统环境，JVM 上 mock 不出有意义的结果。

但判定逻辑 `SkipRuleEngine` 是**纯函数**（输入 `NodeSnapshot`，输出 `Verdict`），理论上可以单独测。

实际测试靠**自带靶场 + 自动化脚本**：

```bash
./gradlew :demo:installDebug
pwsh -File tools/run-scenarios.ps1 -Label final
```

22 个场景自动跑完并输出通过率。方法见 [开发指南 · 测试](开发指南.md#七测试)。

## 其他

### 能跳其他类型的广告吗？

不能。本应用只处理**开屏广告**——即 App 启动时全屏展示、带「跳过」按钮的那种。

- 信息流广告、横幅广告：无跳过按钮，不处理；
- 视频贴片广告：同理；
- 弹窗广告：弹窗同样会触发窗口切换事件，若它带「跳过」类按钮，在观察窗口内可能被命中——但这属于副产物，不是设计目标。

---

### 耗电吗？占多少内存？

几乎不耗电，内存也很小。

**CPU**：空闲时 `%CPU = 0.0`。服务只在收到窗口事件时工作——没有轮询、没有常驻定时器、没有后台线程。单次扫描是一次节点树遍历，毫秒级完成。

**内存**（实测，Android 17 模拟器）：

| 状态 | PSS |
|------|-----|
| 冷启动 | 24.8 MB |
| 后台空闲 60s | 25.5 MB |
| 扫描广告时 | 24.6 ~ 26.3 MB |
| 30 轮扫描压力测试后 | 25.9 MB（仅 +63 KB） |

无内存泄漏。Native Heap 占 11.7 MB，来自 Kotlin 运行时与系统图形库，属正常水平。

唯一常驻的是前台服务，但它不做事，只挂一条通知。

详见 [保活指南 · 内存占用实测](保活指南.md#内存占用实测)。

---

### 前台服务和常驻通知真的有用吗？

**有用，但可能和你想的不一样。**

实测进程优先级（`oom_score_adj`，越小越不易被杀）：

| 配置 | adj |
|------|-----|
| 普通后台（什么都没有） | 700 |
| 仅前台服务 | 50 |
| 仅无障碍绑定 | 100 |
| 前台服务 + 无障碍 | 100 |

两个反直觉的点：

1. **无障碍绑定本身就把进程提升到了前台服务级别（100）**，所以只要无障碍开着，进程就不算普通后台；
2. **叠加前台服务并不会让优先级更高**（仍是 100），因为系统取的是「最合适档位」。

那前台服务的价值是什么？**在无障碍被关闭时兜底**——此时没有它，进程会掉到 adj=700，很容易被回收；有它则保持 50。

所以：如果你确定无障碍一直开着，关掉常驻通知的实际风险比想象中小。

---

### 支持 Android 版本？

最低 **Android 7.0（API 24）**，最高已验证到 Android 17（API 37）。

`minSdk = 24` 是硬下限：手势点击 `dispatchGesture` 从 API 24 才有，低于此版本 WebView 点击和自绘控件兜底不可用。

---

### 能同时装其他同类 App 吗？

可以，但两个无障碍服务会同时收到事件，可能互相干扰（比如都点击同一个按钮）。建议只保留一个。
